# Azure SDK agent-friendliness benchmark snapshot

> Published: 2026-09-01

## Purpose

This report records one data point on whether an AI coding agent can produce
correct, idiomatic, and buildable Azure SDK projects. It does not determine
overall SDK agent-friendliness.

Baseline results are the primary signal. MCP and skills are secondary
configurations used to observe whether external guidance changes the outcome.

## Configurations

| # | Configuration | Coding-agent assistance |
|---:|---|---|
| 1 | Baseline | No Azure-specific tools or skills |
| 2 | Azure MCP + general skills | Azure MCP and general Azure skills |
| 3 | Azure MCP + general + SDK skills | Azure MCP, general Azure skills, and language-specific SDK skills |

For Data point 2, configurations 2 and 3 also include Foundry MCP.

## Methodology

### Benchmark scenarios

The multi-service scenarios cover authentication, client setup, CRUD,
pagination, error handling, retries, polling, batch operations, messaging, and
event processing across data-plane and management-plane SDKs.

The Foundry scenarios cover agent lifecycle, file search, function tools,
project resource discovery, dataset lifecycle, evaluation runs, text
translation and transliteration, and single-document and batch document
translation.

Each scenario requests a complete project, testing an end-to-end developer task
rather than isolated API calls.

### Prompt Checks

Each benchmark scenario defines independent requirements in its
`## Evaluation Criteria` section. An LLM reviewer checks the generated project
for the requested packages, clients, authentication, operations, and error
handling. These checks measure task completion and API usability.

For example, a .NET Prompt Check can require the project to reference specific
Azure SDK packages, construct the requested client, and call the APIs needed to
create, list, update, and delete a resource.

### Language Checks

The checks in `criteria/language/<language>.yaml` apply to the matching language.
An LLM reviewer evaluates language-specific authentication, asynchronous usage,
exception handling, and resource management. These checks measure idiomatic SDK
integration.

For example, .NET Language Checks verify that token-based authentication uses a
credential from `Azure.Identity`, asynchronous calls use `await` instead of
blocking with `.Result`, and errors use SDK-specific exceptions such as
`RequestFailedException`.

### Program Checks

Language-specific validation commands check whether the generated project is
structurally valid and buildable. The exact commands vary by language.

For example, the .NET Program Check runs `dotnet build --nologo`. The check
passes when the command exits successfully and fails when compilation or
dependency restoration fails.

## Grading criteria and scoring

The benchmark uses three categories of checks:

| Check type | What it typically measures | How it is evaluated |
|---|---|---|
| Prompt Check | Scenario-specific requirements, such as using the requested package, client, API, authentication method, or SDK operation. | An AI reviewer examines the generated project and passes the check only when the requirement is fully met. |
| Language Check | Language-specific SDK practices, such as authentication, idiomatic client usage, asynchronous patterns, resource cleanup, and error handling. | An AI reviewer examines the generated project and passes the check only when the practice is correctly applied. |
| Program Check | Structural or build validation, such as compiling source files, building the project, or running a configured lint or validation command. | Hyoka runs the configured command. Exit code 0 passes; a nonzero exit code, timeout, or execution failure fails. |

Prompt and Language Checks are judgments made by an AI reviewer. Program Checks
are deterministic command results. A missing, partial, or incorrect
implementation fails the corresponding Prompt or Language Check.

Each applicable check contributes one equally weighted pass or fail point. The
pass rate is:

`passed checks / applicable checks`

Prompt, Language, and Program Checks remain separate. Skipped checks are
excluded, and infrastructure failures are reported separately. Cross-language
totals are informational because scenario and criteria inventories differ.

## Assumptions and limitations

- This benchmark is one data point. Each scenario runs once per configuration,
  and LLM-reviewed checks are nondeterministic.
- Many scenarios specify the expected package, client, or SDK pattern. Results
  are stronger evidence of implementation than independent API discovery.
- Method-specific criteria can reject functionally equivalent SDK patterns and
  may lag current SDK APIs. Some failed checks can therefore reflect rubric
  specificity or staleness rather than failure to complete the requested task.
- Scenario inventories differ by language and cover common tasks rather than
  every library or usage pattern.
- The local-code focus limits opportunities for MCP to help and does not measure
  general tool effectiveness.

## Next steps

The most important next step is to identify more representative developer
scenarios and expand the benchmark to better reflect actual customer usage.

## Data point 1: Multi-service Azure SDKs

**Completed:** 2026-09-01

**Sources:** [ronniegeraghty/hyoka#656](https://github.com/ronniegeraghty/hyoka/pull/656)
and the 2026-09-01 Python and .NET refreshes

### Scope

The dataset contains 210 evaluations across 70 complete comparison sets.
JavaScript/TypeScript and Java use the 2026-08-28 results; Python and .NET use
2026-09-01 refreshes. Go was not evaluated. Program Checks were available for
Python and .NET.

### Results

#### Prompt Checks

| Language | Sets | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|---:|
| Python | 19 | 156/172 (90.7%) | 161/172 (93.6%) | 157/172 (91.3%) |
| JavaScript/TypeScript | 13 | 103/118 (87.3%) | 102/118 (86.4%) | 104/118 (88.1%) |
| Java | 18 | 140/159 (88.1%) | 146/159 (91.8%) | 149/159 (93.7%) |
| .NET | 20 | 105/135 (77.8%) | 110/135 (81.5%) | 109/135 (80.7%) |
| **Total** | **70** | **504/584 (86.3%)** | **519/584 (88.9%)** | **519/584 (88.9%)** |

#### Language Checks

| Language | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|
| Python | 80/95 (84.2%) | 83/95 (87.4%) | 89/95 (93.7%) |
| JavaScript/TypeScript | 88/130 (67.7%) | 92/130 (70.8%) | 91/130 (70.0%) |
| Java | 163/216 (75.5%) | 179/216 (82.9%) | 177/216 (81.9%) |
| .NET | 59/60 (98.3%) | 58/60 (96.7%) | 58/60 (96.7%) |

#### Program Checks

| Language | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|
| Python | 19/19 (100%) | 19/19 (100%) | 19/19 (100%) |
| .NET | 20/20 (100%) | 20/20 (100%) | 20/20 (100%) |

Program Checks were not configured for the historical JavaScript/TypeScript or
Java runs.

#### Duration

| Configuration | Average per evaluation | Difference from baseline |
|---|---:|---:|
| Baseline | 4.01 min | - |
| Azure MCP + general skills | 5.12 min | +1.11 min (+28%) |
| Azure MCP + general + SDK skills | 4.69 min | +0.67 min (+17%) |

### Key findings

- Baseline passed 86.3% of Prompt Checks. Azure MCP and general skills scored
  2.6 percentage points higher; adding SDK skills scored 2.6 points higher.
- Differences varied by language. Adding SDK skills scored higher for Python
  and Java, nearly matched baseline for JavaScript/TypeScript, and scored 2.9
  percentage points above baseline for .NET.
- All Python and .NET Program Checks passed. Assisted configurations took
  longer than baseline.

## Data point 2: Azure AI Foundry SDK

**Completed:** 2026-09-01

**Sources:** [weidongxu-microsoft/hyoka#3](https://github.com/weidongxu-microsoft/hyoka/pull/3)

### Scope

The dataset contains 114 evaluations across 38 complete comparison sets: 10
each for .NET, Java, and Python, and 8 for JavaScript/TypeScript. The baseline
has no Azure MCP, Foundry MCP, or Azure SDK skills. Configuration 2 adds Azure
MCP, Foundry MCP, and general Azure skills. Configuration 3 also adds
language-specific SDK skills.

### Results

#### Prompt Checks

| Language | Sets | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|---:|
| .NET | 10 | 88/90 (97.8%) | 90/90 (100%) | 89/90 (98.9%) |
| Java | 10 | 90/90 (100%) | 88/90 (97.8%) | 88/90 (97.8%) |
| JavaScript/TypeScript | 8 | 67/67 (100%) | 66/67 (98.5%) | 66/67 (98.5%) |
| Python | 10 | 87/89 (97.8%) | 87/89 (97.8%) | 88/89 (98.9%) |
| **Total** | **38** | **332/336 (98.8%)** | **331/336 (98.5%)** | **331/336 (98.5%)** |

#### Language Checks

| Language | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|
| .NET | 23/30 (76.7%) | 24/30 (80.0%) | 23/30 (76.7%) |
| Java | 82/110 (74.5%) | 84/110 (76.4%) | 82/110 (74.5%) |
| JavaScript/TypeScript | 54/80 (67.5%) | 53/80 (66.2%) | 58/80 (72.5%) |
| Python | 40/50 (80.0%) | 41/50 (82.0%) | 42/50 (84.0%) |
| **Total** | **199/270 (73.7%)** | **202/270 (74.8%)** | **205/270 (75.9%)** |

#### Program Checks

| Language | Baseline | Azure MCP + general skills | Azure MCP + general + SDK skills |
|---|---:|---:|---:|
| .NET | 10/10 (100%) | 10/10 (100%) | 10/10 (100%) |
| Java | 10/10 (100%) | 10/10 (100%) | 10/10 (100%) |

| Python | 10/10 (100%) | 10/10 (100%) | 10/10 (100%) |
| **Total** | **46/46 (100%)** | **46/46 (100%)** | **46/46 (100%)** |

Some JavaScript/TypeScript evaluations have two Program Checks.

#### Duration

| Configuration | Average per evaluation | Difference from baseline |
|---|---:|---:|
| Baseline | 6.12 min | - |
| Azure MCP + general skills | 8.06 min | +1.94 min (+32%) |
| Azure MCP + general + SDK skills | 7.49 min | +1.37 min (+22%) |

### Key findings

- Prompt Check rates were effectively tied: 98.8% for baseline and 98.5% for
  each assisted configuration.
- The full configuration had the highest Language Check rate at 75.9%, 2.2
  percentage points above baseline. The general configuration reached 74.8%,
  1.1 points above baseline.
- All configurations passed 100% of Program Checks.
- The clearest Language Check gain from SDK skills was for
  JavaScript/TypeScript: 72.5% compared with 67.5% for baseline and 66.2% for
  the general configuration.
- Assisted configurations took 22% to 32% longer than baseline. SDK skills
  reduced the assisted average by 0.57 minutes.
