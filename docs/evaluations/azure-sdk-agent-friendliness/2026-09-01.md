# Azure SDK agent-friendliness benchmark snapshot

> Published: 2026-09-01

## Objective

This report records one benchmark data point on whether an AI coding agent can
produce correct, idiomatic, and buildable Azure SDK projects. It does not
determine overall SDK agent-friendliness on its own.

Within this snapshot, baseline results are the reference. MCP and skills show
whether external guidance changes the outcome.

## Methodology

### Prompt Checks

Each item in a prompt's `## Evaluation Criteria` is an independent requirement.
The reviewer checks the generated project for the requested packages, clients,
authentication, operations, and error handling. These checks measure task
completion and API usability.

### Language Checks

The criteria in `criteria/language/<language>.yaml` apply to projects in the
matching language. The reviewer evaluates language-specific authentication,
asynchronous usage, exception handling, and resource management. These checks
measure idiomatic SDK integration.

### Program Checks

The configured build command restores and compiles the generated project. This
checks package selection, API signatures, dependencies, and project structure.
Program Checks were not available in the historical results below.

### Prompt coverage

The prompts cover authentication, client construction, CRUD, pagination, error
handling, retries, polling, batch operations, and event processing. This tests
the developer experience rather than isolated API calls.

## Grading criteria and scoring

Each applicable criterion produces an equally weighted pass or fail point. The
pass rate is passed checks divided by applicable checks. Categories remain
separate, skipped checks are excluded, and infrastructure failures are reported
separately. Cross-language totals are informational because prompt and criteria
inventories differ.

## Multi-service Azure SDK benchmark

**Completed:** 2026-08-28  
**Source:** [ronniegeraghty/hyoka#656](https://github.com/ronniegeraghty/hyoka/pull/656)

### Scope

| Configuration | Coding-agent assistance |
|---|---|
| Baseline | No Azure-specific tools or skills |
| Azure MCP and skills | Azure MCP and general Azure skills |
| Azure SDK skills | Azure MCP, general Azure skills, and language-specific SDK skills |

The primary run produced 216 evaluations across 72 comparison sets. Seven
controlled retries completed, four were selected, and the final dataset contains
207 evaluations across 69 complete sets. The environment used Copilot SDK v1,
Copilot CLI v1.0.81-11, and Azure MCP 3.0.0-beta.38.

Program Checks and Go were unavailable. Three unresolved sets were excluded:
.NET managed identity, Java storage account management, and
JavaScript/TypeScript Event Hubs.

### Key findings

- In this snapshot, baseline passed 86.9% of Prompt Checks without
  Azure-specific assistance.
- Azure MCP and skills improved Prompt Checks by 0.5 percentage points; Azure
  SDK skills improved them by 3.2 points.
- Gains were concentrated in Python and Java. JavaScript/TypeScript was nearly
  unchanged, and the Azure SDK skills configuration tied baseline for .NET.
- Assisted configurations took longer than baseline.
- All 697 primary and 29 retry Azure MCP calls succeeded without a timeout.

### Assumptions and limitations

- This benchmark is one data point and cannot establish overall SDK
  agent-friendliness.
- This historical run has no Program Checks, Go results, or .NET Language Checks.
- Each prompt ran once per configuration; model variability was not measured.
- LLM-reviewed checks are nondeterministic and used one reviewer model.
- Many prompts specify the expected package, client, or SDK pattern, providing
  stronger evidence of implementation than independent API discovery.
- The prompts cover common tasks, not every library or usage pattern.
- The local-code focus limits opportunities for MCP to help. Configuration
  comparisons do not measure general tool effectiveness or independently prove
  that the SDK is agent-friendly.
